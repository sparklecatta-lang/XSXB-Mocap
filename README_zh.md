# QuadMocap

从 AI 生成的双视角视频里，给**绑好骨的四足动物**做动作捕捉。以本地一键网页应用的形式运行。
你提供一只绑好骨的动物，工具会：渲染给视频模型（如 Seedance）用的起始帧；用这只 rig 的合成渲染训练关键点检测器；
把 rig 拟合到生成的视频上。输出 Blender 动作、`.blend` 和 FBX。

[English](README.md)

![示例：每对左边是原视频，右边是拟合结果。上=正面，下=侧面。](examples/cat/videos/5456/fit/compare_sheet.jpg)

*示例猫，第 0 / 50 / 100 / 150 帧。结果**还不完美**，见[局限](#局限)。*

## 来源

工作流来自 YouTube 博主 **Can It Code?** 的视频
[「AI Can Now Animate Any Monster」](https://www.youtube.com/watch?v=AS92HYsEBqo)：用视频模型生成双视角视频，
用 rig 的合成渲染训练基于 DINO 的关键点检测器，三角化，再拟合骨骼。
本仓库是独立重新实现，并做了下面这些改动。与原视频作者无关联。

## 我们的改动

| | 原工作流（按我们的理解） | 本仓库 |
|---|---|---|
| 拟合目标 | 两视角三角化出 3D 点，再按 3D 点拟合骨骼 | **直接对齐两个视角的 2D 检测**（重投影误差），不做三角化 |
| 信号 | 稀疏关键点 | 关键点 **+ 稠密表面对应**：检测头逐像素预测该点在网格上的 rest 位置，经 KD 树匹配到顶点，蒙皮后的顶点也参与拟合 |
| 视频漂移 | — | 视频模型的正面那格会漂移（缩放、往前凑）。拟合器给正面每帧解一个**平滑的缩放 + 竖直位移** |
| 训练数据 | — | 30% 的合成样本带**残影**，模拟生成视频里快速动作的效果：四肢、尾巴附近姿势的半透明重影。标签和 mask 只取主姿态，检测器学会忽略残影 |
| 评估 | — | **合成真值对照**：用同样的相机渲染 rig 自带动画，跑完整流程，量 3D 误差 |
| Rig | 单一生物 | **任意绑好骨的四足**，一份 JSON 配置（骨名、关键点、关节限制、辅助骨、朝向） |

其他：骨长固定（只解关节旋转）；关节限制、时序平滑、脚不穿地面；整段序列联合优化；合成数据里变形过大的样本（边长拉伸）不参与训练。

### 对照实验数据

同一份检测结果、同一个 rig，只有拟合方法不同（`fit.py --mode ours` 对比 `--mode triangulate`）。

**合成走路，120 帧，有真值**（对齐骨盆后的 3D 关键点平均误差，cm）：

| 方法 | 全部关键点 | 四肢 | 尾巴 |
|---|---|---|---|
| 先三角化再拟合（原方式） | 3.87 | 4.69 | 2.75 |
| **我们** | **3.58** | **4.29** | **2.51** |

![上表的柱状图](examples/cat/benchmark/chart.svg)

整体误差约低 8%，四肢低 9%。骨盆点对齐后恒为 0，不计入。数据与命令见 [`examples/cat/benchmark`](examples/cat/benchmark) 和[示例说明](examples/cat/README.md#benchmark)；
`src/synth_benchmark.py` 可以对任意项目跑完整流程（渲染 → 视频 → 检测 → 两种拟合 → 评估）。
换成新检测器之前（训练数据不带残影），同一段视频上差距更大：我们 3.53 / 4.30 / 2.65 cm，三角化 4.41 / 5.28 / 3.64 cm（全部 / 四肢 / 尾巴）。
新检测器主要让三角化变好了，我们的拟合基本不变。

**真实 Seedance 视频（示例猫，193 帧）**：没有真值，这里是拟合后关键点与检测点的 2D 距离中位数（px，单格 834×556）：

| 方法 | 正面 | 侧面 |
|---|---|---|
| 先三角化再拟合 | 9.7 | 8.9 |
| **我们** | **9.0** | **7.5** |

旧检测器：三角化 10.4 / 8.3，我们 10.2 / 7.2。另一段视频（相机 0° 俯角，193 帧）：三角化 10.3 / 9.3，我们 9.4 / 8.2（旧检测器为 11.5 / 9.1 和 10.4 / 8.1）。

## 环境

- Windows 10/11 或 Linux，NVIDIA 显卡 + CUDA（测试：RTX 5060 Ti 16 GB）。
- [Blender](https://www.blender.org/) 4.2 及以上（测试 5.1.2），作为外部程序无头调用。
- Python 3.10–3.12。
- 仓库和项目路径**不要含中文等非 ASCII 字符**（Windows 上 OpenCV 读不了这类路径）。

## 使用网页应用

运行 `start.bat`（或 `python app/server.py`），打开 http://127.0.0.1:7860，只监听本机。
找不到 Blender 时，在「设置」里填 blender.exe 路径。每一步都显示进度和日志。

1. **导入 rig**：上传 `.blend` / `.fbx` / `.glb`（一个骨架 + 蒙皮网格）。会清理场景（删其他物体、应用变换、合并网格），
   并按骨名猜一份**配置草稿**（左右标记、朝向、关键点、脚）。导入时还会校验网格是否跟随导出的蒙皮（每次渲染和导出前也会校验）。请在配置编辑器里检查，尤其是关节限制，默认值很通用。
   文件里如果带动画（例如走路循环），会当作合成数据的姿势先验。
2. **生成起始帧**：上=正面、下=左侧面，同一正交比例，并输出 `cameras.json`。把这张图作为图生视频的首帧。
3. **生成训练数据并训练**（一次跑完）：在关节限制内随机摆姿、双视角渲染（RGB、rest 坐标图、关键点标签；其中 30% 带残影），再在冻结的 DINOv2 主干上训练一个小卷积头。
   默认值就是推荐值：1500 组、3 个并行 Blender、6000 步（RTX 5060 Ti 上约 40 分钟）。勾选「复用已有训练数据」可以只重新训练。
4. **上传视频 → 检测 + 拟合 → 预览对比 → 导出**：检测叠加视频、拟合对比视频、`mocap.blend` 和 `mocap.fbx`（烘焙好的动作，可进 UE / Unity 等）。

不想训练先试试：**新建 → 从示例复制：cat**。示例带训练好的检测头、起始帧和测试视频，可以直接做第 4 步。

### 生成视频

把起始帧作为图生视频的首帧，要求上下两格完全同步、镜头不动。示例视频（Seedance）用的提示词：

> 上下画面需要完全同步。小猫从站立状态开始欢快地奔跑，脚步非常得意，自在，然后停下……

视频要保持起始帧的布局（上=正面，下=侧面）。分辨率随意，只要宽高比一致，相机按宽度缩放。

## 后处理建议

拟合器对视频的每一帧都求解，即使有平滑项，原始动作也会**逐帧抖动**。请把 `mocap.blend` / `mocap.fbx` 当作原始捕捉数据，用之前先清理。通用做法：

1. **对旋转做低通滤波，而不是直接滤欧拉角数值。** 每根骨：把旋转关键帧转成四元数，保持同一半球（`dot(q[t], q[t-1]) < 0` 时取反），
   对每个分量做零相位低通（如 Butterworth，`scipy.signal.filtfilt`，2 阶，24 fps 下截止约 4–6 Hz），归一化，再转回骨骼的旋转模式并保持欧拉角连续。
   骨架物体的位移和旋转单独滤，截止频率更低（约 2–3 Hz）。手动快速处理可以用 Blender 4.0+ 的 *曲线编辑器 → 键 → 平滑 → Butterworth 平滑*。
2. **着地时锁脚。** 用脚部关键点找接触帧（连续几帧高度低、速度慢），在接触段用 IK 把脚钉在平均位置，前后各过渡几帧，再烘焙。
3. **或者在拟合时就加大平滑。** 把项目配置里的 `fit.w_smooth`（默认 200）调大，重新「检测 + 拟合」。会牺牲一点重投影精度换更少的抖动，可对比前后的 `fit_report.json`。
4. **对照视频检查。** 重新生成对比视频（「预览对比」），确认跳跃、落地等快动作没有被抹平，只在需要的地方降低截止频率。

给编程 agent（Claude Code、Codex 等）的提示词示例，在本仓库里运行：

```text
用 Blender 无头打开 workspace/<项目>/videos/<id>/fit/mocap.blend。骨架上的动作是逐帧拟合的，有抖动。
写一个 Blender Python 脚本：对每根 pose bone，把旋转关键帧转成四元数（保持半球连续），对每个分量做零相位 2 阶 Butterworth 低通
（scipy filtfilt，按场景帧率截止 5 Hz），归一化，转回骨骼的旋转模式（XZY 欧拉角，保持连续），每帧写一个关键帧。
骨架物体的位移和旋转用 2.5 Hz 截止平滑。不要改骨长和 rest pose。在同目录保存 mocap_smooth.blend，
用和 src/bl_apply.py 相同的 FBX 设置导出 mocap_smooth.fbx，并报告每根骨的最大改动角度。
```

```text
用 workspace/<项目>/videos/<id>/fit/fit.npz、src/rigtorch.py 和项目的 config.json，逐帧算出每个脚部关键点的世界坐标。
脚离地低于 2 cm 且速度低于 0.15 m/s、并持续至少 3 帧的，标为接触帧。在 mocap_smooth.blend 里，接触段用 IK 约束把脚钉到
接触段平均位置的目标空物体上，约束强度前后各用 3 帧过渡，烘焙成新动作，保存为 mocap_clean.blend。列出每只脚找到的接触区间。
```

```text
用起始帧相机重新渲染 mocap_clean.blend 的对比视频（参考 src/bl_apply.py 的 render 模式和 src/compose_compare.py），
给我第 0、50、100、150 帧的前后对比拼图，用来检查快动作有没有被抹平。
```

## 局限

示例结果**还不完美**：

- **抖动**：每帧单独拟合，原始动作逐帧抖动，见[后处理建议](#后处理建议)。
- **尾巴**最差（残差最大），正面视角里尾巴偏高。
- 奔跑的**腾空帧**略微偏高。
- 还**没有脚着地锁定**，接触地面时脚会滑。
- 视频模型的正面那格有漂移（约 5% 缩放、往前凑），漂移修正只能吸收一部分。
- 检测器只用 1500 组合成数据训练（30% 带残影）；留出的合成测试集误差均值 10.0 px、中位数 4.4 px（448 px 裁切，含残影样本），尾尖和后脚趾最差。
- 残影训练只在合成数据和两段残影不多的真实视频上验证过，还没在残影很重的视频上测试。没有模拟运动模糊；合成的快速模糊走路（`--stride 4 --blur 5`）用新旧检测器都是约 5.8 cm。
- 通用 rig 目前只在猫和一个程序生成的方块测试 rig（[`tests/make_test_rig.py`](tests/make_test_rig.py)：`.L/.R` 命名、不同朝向、带缩放、两块网格）上测过，还没在很多真实 rig 上验证。草稿配置的关节限制很通用，一般需要手改。

## 换主干（DINOv3）

主干用 `transformers.AutoModel` 加载，拿到权限后：
`python src/download_weights.py --model facebook/dinov3-vitb16-pretrain-lvd1689m`（需在 Hugging Face 同意协议并登录），
再把配置里的 `train.backbone` 改成 `weights/dinov3-vitb16-pretrain-lvd1689m`，重新训练。
